# Технический аудит WindowsProfileMigration v1.10.1

Автор проекта: Arhivater. Базовый коммит v1.10.0: `0e6f900e0e7f77d5b67bc95d45b53ddf2441e14c`.

## Архитектура и границы проверки

| Компонент | Вход и основные вызовы | Зависимости |
| --- | --- | --- |
| `Start.cmd` | Выбирает 64-разрядный Windows PowerShell, запускает `Bootstrap.ps1`, возвращает код завершения. | CMD и системная копия Windows PowerShell. |
| `Bootstrap.ps1` | `Resolve-OriginalFolder` → локальный путь или UNC → однократный запуск с правами администратора → `ProfileMigration.ps1`. | UAC, WScript Network, CIM или SMB для сопоставления подключённого диска. |
| `ProfileMigration.ps1`, оркестрация | Проверка платформы и прав → меню → отчёт → проверка USMT → выбранное действие. Режим автоматического импорта принимает ZIP и явное назначение. | 64-разрядный Windows PowerShell 5.1, CIM, реестр, NTFS, Microsoft ADK/USMT и .NET Framework. |
| Экспорт | `Select-Profile` → `Do-Export` → манифест SHA-256 → `ScanState` → проверка области и хранилища → дополнения → ZIP → контрольная сумма → публикация. | ScanState, UsmtUtils, System.IO.Compression, выбранный выгруженный профиль. |
| Импорт | `Select-Archive` → `Do-Import` → проверка формата, доказательства области, манифестов и USMT-хранилища → проверка SID назначения → `LoadState` → сравнение файлов → дополнения. | LoadState, UsmtUtils, NTAccount/SID, CIM, локальная или доменная учётная запись. |
| Дополнения | `Export-*` и `Restore-*` обрабатывают разрешённые данные браузеров, Проводника, сетевых дисков, 1С и рабочего стола. | Файлы профиля, HKU, NTUSER.DAT, особенности версий приложений и Windows. |
| Сетевой перенос | `Prepare-RemoteReceiver` → `Do-RemoteDeploy` → WinRM и проверка получателя → подтверждённые блоки ZIP → проверка SHA-256 → автоматический импорт → отчёт получателя. | PowerShell Remoting, административный доступ, штатные политики Windows и доступный USMT на получателе. |
| Восстановление | JSON состояния → меню 4 → проверка владельца операции, назначения и путей перед доступными действиями. | Локальная файловая система, зарегистрированный профиль и состояние USMT. |
| `README.txt` | Пользовательский маршрут от запуска до проверки результата и отчёта. | Интерактивная консоль Windows. |

Исходная реализация уже ограничивала экспорт выбранным профилем и проверяла ZIP. Наиболее рискованные границы проходили между проверкой и повторным открытием файла, между записью состояния и запуском LoadState, а также между отдельными вызовами WinRM. Один основной сценарий сохранён с отдельными функциями для проверки данных, транспорта и состояний. У комплекта один вход через `Start.cmd`, а подготовка к работе и тесты не требуют редактирования скриптов.

Приоритизация сделана по последствиям для пользовательских данных. Вначале рассмотрены область экспорта, проверка входного архива и запись на получателе. Затем проверены отказоустойчивость, очистка, дополнительные настройки и диагностика. Проверки исходного и итогового кода включают статическое чтение, синтетические файлы, тестовые двойники системных операций и отдельную проверку совместимости синтаксиса.

## Транспорт для больших ZIP

| Вариант | Перезапуск после обрыва | Требования и стоимость |
| --- | --- | --- |
| `Copy-Item -ToSession` | Может использовать готовый архив от предыдущего запуска. При обрыве посередине заново передаёт файл. | Работает через существующий WinRM. Передача проста, но повтор большого ZIP дорог. Сохраняется для небольших файлов комплекта. |
| SMB + `Robocopy /Z` | Поддерживает режим возобновления. Контрольную сумму следует сверять отдельно. | Нужны доступный ресурс SMB и согласованные права на него. Может давать лучшую пропускную способность для большого ZIP в подготовленной локальной сети. |
| Блоки через существующий WinRM | Подтверждается запись блока. При повторе сверяется префикс, а перед публикацией сверяется полный SHA-256. | Отдельный SMB-ресурс не требуется. У передачи больше вызовов и накладных расходов. Время и объём памяти на вызов ограничены размером блока. |

Для прямого переноса выбран последний вариант. Пользователь подтверждает конкретного получателя и пользователя назначения. Программа использует действующую конфигурацию WinRM и отдельное подтверждение штатной подготовки получателя. Пропускная способность и время восстановления соединения измеряются в W19. [PowerShell Copy-Item](https://learn.microsoft.com/powershell/module/microsoft.powershell.management/copy-item?view=powershell-5.1) · [Robocopy](https://learn.microsoft.com/windows-server/administration/windows-commands/robocopy)

## Форматы и остаточные риски

- Схемы 1–6 доступны для проверки. Для LoadState требуется схема 7 с доказательством области одного профиля и целостности манифестов. ZIP и контрольные суммы проверяют целостность. Доверие к происхождению обеспечивается хранением комплекта и архива в подконтрольной администратору папке.
- В сравнении SHA-256 после LoadState участвуют заявленные пользовательские папки и зарегистрированные дополнения. Полнота переноса приложения подтверждается входом под получателем, запуском приложения и проверкой его настроек.
- Экспорт не создаёт снапшот тома. Проверка выгруженного профиля и повторная сверка уменьшают вероятность несогласованных данных. Согласованность при одновременных изменениях на Windows зависит от поведения USMT и файловой системы.
- Quick Access, расположение значков, GPO и браузерные профили зависят от версии Windows, приложений и среды получателя. Копирование поддерживаемых настроек проверяется отдельно от работоспособности приложения в новой сессии.
- Для NTFS/SMB, UAC, реестра, совместимости Windows 10/11, USMT, доменов и WinRM требуется стенд. Linux-проверки покрывают общий код, обработку файлов и логику при подмене системных вызовов.

# Испытания WindowsProfileMigration v1.10.1

Автор проекта: Arhivater.

## Стенд и данные

1. Подготовьте виртуальные машины Windows 10 и Windows 11 с контрольными точками. Для пары Windows 11 → Windows 11 используйте две машины. На каждой должны быть 64-разрядный Windows PowerShell 5.1, администратор и USMT из подходящего Windows ADK. Один тестовый снимок оставьте без USMT.
2. Создайте на источнике обычные учётные записи `WpmSource` и `WpmOther`. Добавьте разные файлы-маркеры в их папки. Для выбранного профиля подготовьте пустой файл, файл с кириллицей и пробелами в имени, несколько папок и достаточно большой файл для проверки отмены и сетевой передачи.
3. Добавьте синтетические закладки и историю в Chrome, Edge и Яндекс Браузер. Закрепите вспомогательную папку в Проводнике, сохраните тестовый список баз 1С, назначьте тестовому пользователю буквы сетевых дисков и измените расположение значков. Используйте данные и UNC-ресурсы стенда.
4. Проверьте, что сессия `WpmSource` завершена, а администратор вошёл отдельно. На получателе подготовьте существующий профиль с собственным файлом-маркером для проверки защиты от перезаписи. Для каждого прогона успешного импорта используйте нового получателя или верните машину к контрольной точке.
5. Запишите SHA-256 синтетических файлов и их пути. После каждого прогона сверьте эти файлы на источнике и получателе, а также сохраните итоговые TXT обоих ПК и JSON состояния операции. Перед передачей отчётов удалите реальные имена компьютеров, учётных записей и сетевых ресурсов, если они случайно попали в стенд.

Запуск автоматических проверок из корня исходников или распакованного комплекта:

```powershell
powershell.exe -NoProfile -NonInteractive -File .\tests\Run-Tests.ps1
```

Успешный запуск завершается кодом 0. Проверки используют синтетические файлы и подмены системных вызовов. Этапы ниже выполняются отдельно с Windows, USMT и реальным входом под восстановленным пользователем.

## Запуск и меню

| ID | Испытание | Ожидаемый результат |
| --- | --- | --- |
| W01 | Из обычной учётной записи запустить `Start.cmd` и один раз подтвердить UAC. Повторить с вводом данных другого администратора и из уже повышенной консоли. | Открывается одно меню. Текущий интерактивный пользователь определяется отдельно от администратора. Выход через `0` возвращает код 0. |
| W02 | Отменить UAC, затем повторить запуск успешно. Выполнить несколько вводов вне диапазона, нажать `0` в каждом меню, отменить подтверждения через `0` и `2`. | Отмена UAC возвращает 1223 и записывает диагностический TXT. Ошибочный ввод не запускает действие. Отмена возвращает назад. |
| W03 | Запустить комплект из корня локального диска, с флешки, из папки с пробелами, кириллицей и `!`, с подключённого сетевого диска и напрямую по UNC. Повторить для администратора без доступа к общей папке. | В доступных местах работает исходный абсолютный путь. При недостатке доступа выводится ошибка. Старые отчёты сохраняются. |
| W04 | На снимке без USMT отказаться от скачивания, отказаться от установки после загрузки и затем принять оба запроса. Повторить при блокированной сети. | Установка начинается после обоих подтверждений. Отчёт содержит ошибку или код завершения. При 3010 требуется перезагрузка. |

| W06 | Проверить ZIP через пункт 3. Повторить с файлом из другой папки, архивом-папкой, представительной копией каждого поддерживаемого формата, повреждённым ZIP и копией с нарушенным манифестом или хранилищем. | Корректные архивы схем 1–7 распознаются и проверяются. LoadState разрешён для схемы 7 с подтверждённой областью профиля. Неизвестные версии и нарушенная целостность блокируют импорт. Проверка не создаёт пользователя. |
| W07 | Импортировать архив в пустое назначение. Войти под получателем и сравнить файлы, SHA-256 и содержимое пользовательских папок. | Отчёт отдельно показывает целостность архива, завершение LoadState и проверку файлов. Пользовательская приёмка подтверждается входом и сверкой данных. |

Закрываются индикаторы, итог указывает этап. После прерванного LoadState повторный запуск проверяет состояние целевого профиля. |
| W11 | Прервать скрипт или выключить тестовую ВМ, когда создаётся ZIP, при распаковке и после начала LoadState. Повторить после перезагрузки. | Готовые ZIP и незавершённые копии различимы. Состояние и отчёт доступны. Очистка относится только к учтённым временным данным. Исходный и существующий целевой профили сохраняются. |

Сетевые сбои искусственно вызываются только на виртуальных адаптерах стенда. Повторите W05–W08 для пар Windows 10 → 10, Windows 10 → 11 и Windows 11 → 11. Учётные записи для W07, W17 и W18: локальная → локальная, доменная → доменная в одном и разных доменах, доменная → локальная. Зафиксируйте каждый фактически проверенный вариант отдельно.

## Если тест не прошёл

1. Зафиксируйте ID, версию комплекта, сборки ОС, архитектуру, направление переноса, параметры сети, действие и время.
2. Сохраните оба итоговых TXT, журналы USMT, состояние операции и SHA-256 ZIP. Для проблем со значками добавьте разрешения экранов, DPI и снимки рабочего стола.
3. На получателе проверьте состояние через пункт 4. При неизвестном результате LoadState остановите повторные прогоны с этим назначением. Для нового испытания восстановите снимок ВМ или возьмите чистый профиль.
4. Отметьте `FAIL` для подтверждённого отклонения, `BLOCKED` для отсутствующего оборудования или доступа, `NOT_TESTED` для ещё не выполненного сценария. Для `PASS` приложите воспроизводимое доказательство.

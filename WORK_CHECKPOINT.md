# Точка продолжения WindowsProfileMigration v1.10.1

Репозиторий `Arhivater/WindowsProfileMigration`. Рабочая ветка `release/v1.10.1`. База версии v1.10.0 в `main`: `0e6f900e0e7f77d5b67bc95d45b53ddf2441e14c`.

## Состояние на паузе

- В ветке собраны исправления запуска, экспорта, ZIP и USMT, импорта, дополнительных настроек, состояния и прямого переноса. Рабочие данные и незавершённые операции используют закрытый каталог. Новый WinRM-протокол продолжает с проверенного смещения и защищает от повторного LoadState.
- После последних изменений Linux PowerShell 7.7.0 выполнил `tests/Run-Tests.ps1` с результатом `SUMMARY total=72 pass=72 fail=0`. Эти проверки включают синтетические файлы, тестовые двойники и парсер.
- PSScriptAnalyzer 1.25.0 сообщил 0 замечаний по синтаксису и командлетам 5.1. Пять замечаний по типам относятся к четырём обращениям к Windows Forms после `Add-Type` и одному обращению к `FileSystemAclExtensions` в ветке PowerShell Core.
- Первый запуск Windows Server 2022 с Windows PowerShell 5.1 дал **71 PASS / 3 FAIL**. Сбой зафиксирован в [GitHub Actions](https://github.com/Arhivater/WindowsProfileMigration/actions/runs/44785580231).
- Для этих трёх результатов уже внесены изменения. `1d893bc` передаёт командную строку CMD в нативном виде в тесте, `9f73314` закрывает поток манифеста профиля при ошибке, `3247acb` делает то же для манифеста Extras. В двух последних случаях добавлена проверка повторного эксклюзивного открытия файла.
- Локальный пробный ZIP для `9526d74` прошёл проверку CRC, точного содержимого 15 файлов и прогона после распаковки. После исправлений Windows комплект требуется собрать заново. Тег и релиз v1.10.1 на момент паузы ещё не создавались.

## Продолжить в этом порядке

1. Открыть [проверки ветки](https://github.com/Arhivater/WindowsProfileMigration/actions?query=branch%3Arelease%2Fv1.10.1). Проверить повторный запуск Windows PowerShell 5.1 после трёх последних исправлений. Ожидаются 74 теста, включая два нативных сценария для CMD и путей Windows.
2. При красном прогоне прочитать `gh run view <id> --log-failed`. Если CMD-тест снова упадёт, проверить фактическое выполнение `Start.cmd` из каталога с кириллицей, пробелами и `!`, отдельно для кодов 0, 19 и 1223. Для ошибок обработки манифеста проверить, открывается ли файл с `FileShare.None` сразу после отказа. Проверить оставшееся использование `File.ReadLines` в `Inspect-UsmtFileScope`: при исключении чтения дескриптор должен закрываться на PowerShell 5.1.
3. После исправлений повторить автоматический прогон и проверку совместимости.

   ```powershell
   pwsh -NoLogo -NoProfile -NonInteractive -File tests/Run-Tests.ps1
   pwsh -NoLogo -NoProfile -NonInteractive -File tests/Check-Compatibility.ps1
   ```

4. Обновить `AUDIT_REPORT.md` двумя найденными на Windows дефектами закрытия потоков, а `TEST_CHECKLIST.md` и `CHANGELOG.md` фактическими результатами повторного прогона. В текущем аудите 52 исправления до учёта этих двух находок. Ошибка кавычек тестового запуска относится к тесту.
5. Собрать `WindowsProfileMigration_v1.10.1_Arhivater.zip` из финального коммита. Включить `Start.cmd`, `Bootstrap.ps1`, `ProfileMigration.ps1`, `README.txt`, четыре отчётных Markdown-файла и каталог `tests`. Проверить CRC, совпадение байтов файлов с Git и тесты из чистой распаковки. Сверить SHA-256 ZIP.
6. Создать тестовый prerelease v1.10.1 на проверенном коммите с ZIP и отдельными `AUDIT_REPORT.md`, `TEST_CHECKLIST.md`, `CHANGELOG.md` и `TESTING_GUIDE.md`. Проверить ссылки и размеры загруженных файлов.
7. Выполнить W01–W22 на синтетических профилях Windows 10/11 по `TESTING_GUIDE.md`. До такого прогона реальная миграция USMT, WinRM, UAC, домены и приёмка профиля остаются **BLOCKED**. Windows Server подтверждает совместимость отдельных компонентов Windows PowerShell 5.1 и файловой системы.
